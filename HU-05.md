# Sistema de Turnos: Cancelación, Gestión y Separación de Vistas

## 1. Contexto
Hoy el sistema permite [reservar turnos / listar turnos]. Este cambio agrega:
1. Cancelación de turnos por parte del ciudadano.
2. Gestión de servicios y atención de turnos por parte del admin.
3. Separación de las vistas de empleado y admin.

## 2. Roles
| Rol | Descripción |
|---|---|
| Ciudadano | Reserva y cancela sus propios turnos |
| Empleado | Atiende turnos (ver cola, marcar como atendido) |
| Admin | Gestiona servicios y ve/atiende todos los turnos |

## 3. Estados de un turno
`pendiente → atendido`
`pendiente → cancelado` (solo por el ciudadano) `(?)`

## 4. Funcionalidades

### 4.1 Cancelar turno (Ciudadano)
**Historia:** Como ciudadano quiero cancelar mi turno para liberar el cupo si no puedo asistir.

**Criterios de aceptación**
- [ ] Solo puede cancelar turnos propios.
- [ ] Solo se pueden cancelar turnos en estado `pendiente`.
- [ ] Se pide confirmación antes de cancelar.
- [ ] El turno cambia a `cancelado` y el cupo queda libre.
- [ ] Se muestra un mensaje de éxito o error.

**Reglas de negocio**
- Anticipación mínima para cancelar: `(?)` horas.

- [ ] Listado de turnos (mantener el formato actual).

### 4.4 Separación de vistas
| Vista | Ruta | Acceso | Contenido |
|---|---|---|---|
| Empleado | `/empleado` | Empleado | Cola de turnos, acción "Atender" |
| Admin | `/admin` | Admin | Todo lo del empleado + CRUD de servicios |

- [ ] Un rol no puede acceder a la ruta de otro (redirigir o mostrar 403).
- [ ] La protección debe aplicarse también en el backend, no solo ocultando botones.
